# AnonyMed – Manual

AnonyMed redacts patient documents on your own computer before you hand them to a language model, and puts the clear data back afterwards. Nothing leaves the computer except the search in your own Nextcloud address book.

## Installation

**Packaged:** unpack the archive for your system (macOS: drag `AnonyMed.app` to Applications; Windows and Linux: put the folder `AnonyMed` anywhere). It contains the desktop interface `anonymed-gui` (macOS: the app) and the command line `anonymed`. The packages are not code-signed; macOS asks on first start (right-click, Open), Windows shows the SmartScreen notice.

**From source:** Python 3.12 or newer and [uv](https://docs.astral.sh/uv/), then

```sh
uv sync --extra ocr --extra codes --extra gui
uv run anonymed gui --language en
```

Tesseract is used as a second OCR engine when it is installed (macOS: `brew install tesseract tesseract-lang`, Ubuntu: `apt install tesseract-ocr tesseract-ocr-deu`); it is found in the usual places even when the app is started from the Finder. It is not required, RapidOCR is included. To prefer Tesseract, put `backend = "tesseract"` under `[ocr]` in the configuration file (`anonymed konfig` shows the path) or set `ANONYMED_OCR=tesseract`.

**Language.** The interface follows the system language; `--language en` or `--language de` on the command line, the menu *Language* in the window, or `ANONYMED_SPRACHE=en` choose it explicitly. Reports and command-line messages are in German.

## First start

AnonyMed creates the pseudonym database (`pseudonyme.sqlite`) and the secret key next to it (`pseudonymschluessel.txt`) in the user data folder; `anonymed konfig` shows the paths. **Back up the key.** With the same key every computer produces the same pseudonyms; without it old identifiers cannot be reproduced. The database holds the mapping pseudonym → clear data for re-identification; it is patient data and stays on the computer. `ANONYMED_DATENORDNER` puts database, key and configuration into one folder, for a portable installation on an encrypted stick.

Set up the address book once (command line):

```sh
anonymed kontakte einrichten --url https://your-nextcloud.example --benutzer yourname --adressbuch patients
```

The app password (Nextcloud → Settings → Security) goes into the operating system's keyring.

## The eight steps

1. **Patient.** Search the address book (name, year of birth), load a patient file or a vCard. Address books are set up under *Set up address books …*: a local vCard file or a folder of vCard files (exported from Apple Contacts, Thunderbird, Outlook or Nextcloud; stays on the machine) and/or Nextcloud over CardDAV (address, user, app password from Nextcloud → Security; the password goes into the keyring, or into the configuration file where there is no keyring). Hits appear in a list that shows only when there are hits; a click fills the fields. *Patient file …* loads a JSON or TOML file with the identifiers as `anonymed kontakte export` writes them; *Save template …* gives an empty one to fill in. Check the fields: everything listed there will be redacted. Add relatives, referrers and further terms (one per line) or drop a text file with one entry per line onto the field; they are not taken from a contact's notes automatically. *Use this patient*.
2. **Documents.** Drop PDFs, photos or text files (`.txt`, `.md`, `.srt`, `.vtt`, Whisper `.json`, `.eml`, for instance the transcript of a recorded consultation or a patient's e-mail); they are opened at once. Photos and images go on a sheet of the chosen paper size (A4, A5, A3, US Letter, US Legal or "as large as the image"; portrait or landscape follows the image, which is scaled to fit). Pages without a text layer (scans, photos) appear underneath for the clean-up before text recognition, each with a suggestion: straighten the tilt (suggested from 1.2°, angle adjustable), unwarp a photographed sheet, upscale 2×, 3× or 4× (the OCR reads the page at that multiple of the resolution; the page itself is not stored enlarged), letter mode (Lanczos enlargement and sharpened strokes in grey scale; a hard black-and-white threshold lowered the recognition markedly in measurements, so it is never suggested automatically), even out the background, black and white, and under *Further steps*: clean dark borders, remove coloured ink (stamps, highlighter, blue signatures), denoise, raise contrast, sharpen, remove lines, detect orientation (portrait/landscape from the lines, upside-down by a short OCR comparison), rotate in 90° steps. Rectangles drawn on the "after" image erase the region white before the OCR sees it (*Restore erased areas* undoes that). Denoising, contrast and sharpening have strength sliders; erased areas can be taken back one by one with Cmd/Ctrl+Z. Original on the left, result on the right with a movable divider, both views linked when panning (Shift or Option + drag, middle button) and zooming; an upscaled result is shown at the original size, zooming in reveals the gain. *Apply steps to all pages* copies the switches. A learnt super-resolution model for text is not included; it would need extra libraries and models. *Next: analyse*.
3. **Text recognition.** Choose the OCR engine (RapidOCR with bundled models, Tesseract, off) and the language packs (Tesseract: `deu+eng`, the installed languages are listed; RapidOCR: language type `de`, `en`, `latin`). Tesseract takes a bordered table for graphics and skips the cells (a medication table came back as a single word); AnonyMed therefore looks for grids on every page, cuts them out, removes the rules and reads the crop in a second pass as one block; the better reading wins. Measured on synthetic tables with thick borders: 0 of 45 cell words without, 42 with the second pass; pages without a grid are untouched. The *Tables* checkbox switches it off. RapidOCR does not have the problem. With *Structure the recognised text* (on by default) the recognised text appears as Markdown: lines that run to the right margin are joined into paragraphs (hyphenation undone), a taller gap ends the paragraph, lines in a larger face become headings, short bold lines on their own small headings, bullets list items, words far apart table cells (several such lines a Markdown table). Italics are not recognised; the engines report no slant. The structure is computed from the geometry of the OCR lines and applies to the text file, the Markdown and the editor; you correct the structured text. Independently of that, the invisible text layer of the PDF sits word by word on the image words: for corrected or structured text every word is aligned to the OCR word it came from (a corrected word takes the box of the one it replaces, inserted words sit between their neighbours, Markdown characters get no box), so that text can be selected in a PDF reader exactly where it is printed. *Start text recognition* reads all documents on the basis of the cleaned-up pages. Then every page shows the cleaned-up image next to the recognised text, which you correct by hand on OCR pages (*Apply text*); text from a text layer cannot be changed. The correction feeds the text file, the Markdown and the invisible text layer; what the OCR misread in the image you redact later with a box or a mask. *Next: analyse*.
4. **Analyse.** The detection settings: form of the date of birth, barcodes, unreadable lines, medical terms, fuzzy search in text files (speech recognition misspells names the way OCR does), NER. Below it *Recipient*: whoever pseudonymises for someone else (see key capsules) gives that person's public key here. Defaults: mark and protect medical terms, then NER (if the extra is installed). Below it the medical vocabulary with its sources and *Import vocabulary …*: a text file with one term per line, for instance the `.vokabular.txt` written on export, is merged into your own vocabulary and protected from the next analysis on. *Analyse* searches all read documents with a progress bar; the review step opens afterwards.
5. **Review.** Redaction only now; the text is no longer edited here. Traffic-light colours: red will be redacted (dashed when NER or the fuzzy search merely suggest it), yellow was read with low confidence by the OCR (unreadable lines are blanked as a precaution), green stays: medical terms and discarded hits, which remain visible and can be restored with a click. The source of every hit is in the table. A false hit (a drug name that looks like a surname): click it, *Discard hit*. Dragging draws a box with the replacement text from the field next to the buttons; with *Draw mask* a black mask under which text and image disappear; Shift + drag pans the view, Ctrl/Cmd + wheel zooms. *Remember discarded hits for this patient* stores your decisions in the pseudonym store on export: in the next document of the same patient the same text under the same rule starts out green and can be restored. What the OCR misread in the image you redact with a box or a mask; the text itself is corrected in the text-recognition step. Something missed, a handwritten name for instance: drag a box over it. Zoom with Ctrl/Cmd and the wheel or the buttons. A text file appears as text with coloured spans instead of a page image; click a span to select the hit, select text and press *Redact selection* to turn it into a manual hit. Orange spans are the fuzzy search's hits: suggestions worth a look.
6. **Export.** Opening the step first runs the complete finishing phase into a scratch folder, including the re-check of the result against everything from *1 Patient*. The traffic light at the top shows the outcome: green means nothing found any more, ready to export; yellow means released but with warnings you should read; red means data were still found, the export button stays off and a message names the leftovers, which you rework in the review step with a box or a mask. The export then copies the checked files. The report records what was searched again ("Erneut geprüft nach dem Prüfschritt: …") and which hits you kept on purpose; your deliberate decisions and general reminders (clean-up steps, OCR summary, the note that handwriting is not read, blanked unreadable lines, NER counts, fuzzy hits, remembered discards) are listed under *Hinweise*, only what needs attention under *Warnungen* (pages without OCR, NER requested but missing, an uncertain patient match, a failed re-check), and only those turn the light yellow; a passed scan is green. With *Vocabulary of the discarded guesses* (on by default) you also get `name_anonym.vokabular.txt`: the NER and fuzzy hits you discarded in the review, one term per line, for the import in *4 Analyse*; discarded hits of the fixed rules are left out, their text being one of the patient's identifiers. Choose a target folder. Per document you get `name_anonym.pdf` (with a text layer: for scans and photos the OCR text minus the hits is embedded invisibly, also after *rasterise completely*), `name_anonym.txt` (the text in reading order, this is what you give the language model), optionally `name_anonym.md`, and `name_anonym.bericht.json`; a text file yields only `name_anonym.txt` (same extension as the input, subtitle timestamps preserved) and the report. The re-check reads the result again; if an identifier survives, nothing is released and the report says why. OCR pages get preview images: look at them before you pass a scan on.
7. **Re-identify.** Paste the language model's text, pick the person, *Re-identify*. If the text comes from someone else, open their key capsule (*Open capsule …*, see below); its mapping then replaces the local database.
8. **Database.** Where database and key file live (any folders, even apart; a change copies the current files there and renames the old ones), statistics of the pseudonym store (patients, mappings per category, remembered discards, size, integrity, key handle) and backup and restore of everything re-identification needs: database and key file, optionally configuration and vocabulary. The backup is a ZIP with checksums, encrypted with a passphrase (`.zip.gpg`, `gpg --decrypt` opens it too) or, if you insist, plain. Restoring replaces database and key (the current ones are set aside) or merges an archive made with the same key; two different keys cannot be mixed. Nothing is imported while analysed documents are still waiting for export. Command line: `anonymed datenbank status|exportieren|importieren`. *Mr/Ms surname* inserts the salutation by grammatical case, *full name* the name. Mangled pseudonyms (wrong check character) are reported with a suggestion.

## Texts and transcripts

If you record consultations and transcribe them locally, the transcript is a text file: it runs through the same detection as a PDF, and the result is text again with pseudonyms and nothing else changed. Particulars: the fuzzy search finds the patient's name even when misspelt ("Flanz" for "Flantz") but requires a capital letter for names and places; at the start of a sentence it may suggest similar words ("Land" for Lang), which you discard in the review step. `--genau` switches it off. Numbers spoken as words are read as digits before matching: "am einundzwanzigsten Juli neunzehnhundertneunundfünfzig" is the date of birth, "Sieringgasse zweiundvierzig" the street, "acht zwei vier sechs zwei" the postcode; the whole phrase is then replaced.

**Whisper JSON** (openai-whisper, whisper.cpp, WhisperX) is rendered as one line per segment with timestamp and speaker and written as `.txt`; word timings and token ids are not carried over, because the token ids hold the clear text in another form. **E-mails** (`.eml`, dragged or exported from the mail program) become From, To, Cc, Date, Subject, the body (from HTML if need be) and a list of attachment names; routing headers such as Message-ID are left out and attachments are not included: anonymise an attached PDF or photo as a file of its own.

## What is redacted and what is not

Redacted: the name in all spellings, the date of birth in all formats, address, telephone, e-mail, insurance number, patient ID, file numbers, the relatives and referrers you entered, barcodes, and generically every insurance number, IBAN and e-mail address as well as values behind labels such as "Versicherten-Nr." or "Pat.-ID". With NER switched on, additionally people and places the model recognises.

Not redacted: diagnoses, medication, measurements, findings, appointment dates. Not recognised: unknown names when NER is off, and handwriting the OCR does not detect as text; the review step is there for that.

## NER

Named-entity recognition is a statistical model (spaCy, trained on German news) that tags person and place names in free text without a list. It catches the relative or colleague nobody entered, but it guesses: it may tag a drug or a department as a person, and it may miss a name. Therefore its hits are shown in their own colour in the review step, medical eponyms (Alzheimer, Parkinson, Babinski …) and everything the medical vocabulary marks are excluded, ordinary words that are only capitalised because they start a sentence ("Überwiesen hat Sie …") are dropped, and it never decides about the release. The graphical interface runs it by default once the extra is installed, after the vocabulary has marked the page; on the command line it stays opt-in (`--ner`). Install with

```sh
uv sync --extra ner
uv pip install https://github.com/explosion/spacy-models/releases/download/de_core_news_md-3.8.0/de_core_news_md-3.8.0-py3-none-any.whl
```

People it finds become `Person <code>`, places `[Ort <code>]`, with the same keyed hash as the patient's identifier, so the same name gets the same code and the re-identification knows it.

## Medical vocabulary: what guesswork must never touch

NER and the fuzzy OCR search run behind a guard: before they look at a page, every medical term on it is marked, and those spans are off limits to both. The deterministic rules for the patient's own identifiers are unaffected (a patient really called Herz is still redacted). The bundled base vocabulary (about 40 000 German terms) comes from Wikidata (CC0): German labels and synonyms of every item with an ICD-10 code, an ATC code, an INN or a MeSH descriptor in the medical MeSH trees (anatomy, organisms, diseases, drugs, techniques, psychiatry, phenomena); geography and occupations are excluded so that towns and surnames remain recognisable. Inflection, hyphenated compounds (*Parkinson-Syndrom*) and umlaut transliteration are recognised, multi-word terms as a whole.

A second bundled list (`koerperteile_de.txt`, about 580 entries) covers body parts, organs, bones, muscles, vessels and nerves in everyday German plus side and position words (links, rechts, proximal …), because the Wikidata list lacks many colloquial forms (Kopf, Nacken, Oberbauch, Wade) and NER liked to take them for names. A third list (`befundbegriffe_de.txt`, about 370 entries) holds the terms of the clinical examination and the findings report as they head the lines of a status (Konzentration, Haltung, Gangbild, Strichgang, Nierenlager, Reflexe, Sensibilität, Procedere …), which are in neither MeSH nor the body-part list. On the order: the vocabulary marks the page first, then NER runs and skips every entity inside a marked span; NER also drops single words the tagger calls common nouns and unknown single words (compounds such as *Nierenlager*) without a salutation, title or preposition before them.

Your own vocabulary grows with every review: the export writes the discarded guesses to `name_anonym.vokabular.txt`, and *Import vocabulary …* in *4 Analyse* or `anonymed fachbegriffe ergaenzen FILE` merges such a file into `nutzervokabular.txt` in the vocabulary folder (merge, not replace). The vocabulary shields terms from NER and the fuzzy search for every patient; for hits of the fixed rules there is the *Remember discarded hits for this patient* box in the review step.

Your own lists: `anonymed fachbegriffe importieren FILE --name NAME` from MeSH XML (`--format mesh-xml`, the NLM file or a translation), from ICD-10-GM, Alpha-ID-SE or ATC tables (`--format csv --spalte N`) or from any plain list (one term per line). `anonymed fachbegriffe pruefen WORD` tells whether a word is protected, `anonymed fachbegriffe status` lists the sources. SNOMED CT cannot be shipped (a BfArM licence is required); a locally licensed description file imports like any CSV.

## Pseudonyms

The main person is `Patient K7Q4MX` (letters and digits from a keyed hash of name and date of birth, with a check character), relatives `Angehörige K7Q4MX-1`, referrers `Dr. Z1`, streets `[Straße …]`, towns `[Ort …]` and `[PLZ Ort …]`, the date of birth `[geb. 1959]` or `[Alter 66]`. Spelling variants of the same name give the same identifier; when a person only roughly resembles an existing entry, AnonyMed asks. Details in `docs/pseudonyme.md`.

## Key capsules: pseudonyms for a recipient

Patients and colleagues can pseudonymise documents that one particular person, their physician say, is to read in clear later. The recipient publishes an OpenPGP public key (website, letterhead). The sender gives AnonyMed that key in *4 Analyse* under *Recipient* (file or https address; *Check key* shows the fingerprint, which you compare with the recipient by a second channel; AnonyMed pins it and warns when the key at the same address changes) and ticks *Pseudonymise for a recipient*. AnonyMed then derives every pseudonym from a one-time key instead of its own secret, writes nothing to the local database, and puts the mapping back to the clear data, together with the patient's name, date of birth and identifier, into a capsule encrypted to the recipient: `name_anonym.kapsel.asc`. The pseudonymised document and the language model's answer may be sent as usual; the capsule goes to the recipient only, never to the model.

The recipient opens the capsule in *7 Re-identify* (*Open capsule …*) with the private key: from the GnuPG keyring (the agent asks for the passphrase) or from a key file (*Private key*). Every pseudonym of the sender is then resolved, including relatives, referrers and places the recipient's own records never knew; the capsule's patient is matched against the local pseudonym store and the matching entry is named. Why a capsule rather than a pseudonym computed from the public key: a pseudonym anyone with the public key can recompute can be resolved by trying names and dates of birth; a random one-time key that only the recipient can unwrap reveals nothing.

Technology: the extra `pgp` brings pysequoia (Sequoia-PGP), bundled in the desktop app; an installed GnuPG is used when present. Curve25519 and RSA keys work; Curve25519 secret keys exported by GnuPG 2.5 are not yet read by pysequoia, use such keys through the keyring. Your own key without GnuPG: `anonymed schluessel erzeugen --name … --email …` (publish the public key, keep the private one safe; it has no passphrase). With GnuPG: publish `gpg --armor --export <key-id> > anonymed.asc` and the fingerprint from `gpg --fingerprint <key-id>`. `anonymed schluessel zeigen FILE|ADDRESS` prints fingerprint and names of a key.

## Command line

```sh
anonymed anonymisieren befund.pdf --kontakt "Müller 1959"
anonymed anonymisieren scan.pdf --patient patient.json --ocr tesseract --ner
anonymed anonymisieren gespraech.txt --kontakt "Müller 1959"          # transcript, fuzzy search on
anonymed anonymisieren gespraech.srt --patient patient.json --genau   # exact hits only
anonymed pruefen befund_anonym.pdf --patient patient.json
anonymed rueckersetzen brief.txt --kennung K7Q4MX --form anrede
anonymed anonymisieren foto.jpg --kontakt "Müller 1959" --papier letter   # image on US Letter
anonymed anonymisieren scan.pdf --patient patient.json --roh              # OCR text without Markdown
anonymed anonymisieren befund.pdf --patient me.json --empfaenger https://example.org/doctor.asc  # for a recipient
anonymed rueckersetzen brief.txt --kapsel befund_anonym.kapsel.asc       # recipient, GnuPG keyring
anonymed schluessel erzeugen --name "Dr Example" --email doctor@example.org  # key pair without GnuPG
anonymed kontakte lokal ~/Contacts/patients.vcf                          # local address book
anonymed datenbank speicherort --datenbank ~/Safe/anonymed.sqlite --schluessel ~/Safe/key.txt
anonymed datenbank status                                                # statistics
anonymed datenbank exportieren ~/Backups                                 # asks for a passphrase
anonymed datenbank importieren ~/Backups/anonymed_sicherung_2026-11-02_0900.zip.gpg
anonymed fachbegriffe ergaenzen befund_anonym.vokabular.txt           # into your vocabulary
anonymed pseudonyme
anonymed konfig
```

Exit codes: 0 released, 1 input error, 2 not released, 3 pseudonyms left after re-identification, 4 uncertain match (`--gleich KENNUNG` or `--neu`).
