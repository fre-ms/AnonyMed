# AnonyMed – Anleitung

AnonyMed schwärzt Patientendokumente auf Ihrem Rechner, bevor Sie sie einem Sprachmodell geben, und setzt die Klardaten anschließend wieder ein. Nichts verlässt den Rechner außer der Suche im eigenen Nextcloud-Adressbuch.

## Installation

**Fertiges Paket:** Archiv für Ihr System entpacken (macOS: `AnonyMed.app` in den Programme-Ordner ziehen; Windows und Linux: Ordner `AnonyMed` an einen beliebigen Ort). Darin liegen die Oberfläche `anonymed-gui` (macOS: die App) und die Kommandozeile `anonymed`. Die Pakete sind nicht signiert; macOS fragt beim ersten Start nach (Rechtsklick → Öffnen), Windows zeigt den SmartScreen-Hinweis.

**Aus dem Quelltext:** Python 3.12 oder neuer und [uv](https://docs.astral.sh/uv/), dann

```sh
uv sync --extra ocr --extra codes --extra gui
uv run anonymed gui
```

Tesseract wird als zweites OCR-Programm benutzt, wenn es installiert ist (macOS: `brew install tesseract tesseract-lang`, Ubuntu: `apt install tesseract-ocr tesseract-ocr-deu`); es wird an den üblichen Orten gefunden, auch wenn die App aus dem Finder startet. Nötig ist es nicht, RapidOCR ist enthalten. Wer Tesseract bevorzugt, trägt `backend = "tesseract"` unter `[ocr]` in die Konfigurationsdatei ein (`anonymed konfig` zeigt den Pfad) oder setzt `ANONYMED_OCR=tesseract`.

**Sprache.** Die Oberfläche folgt der Systemsprache; `--sprache en` oder `--sprache de` beim Start, das Menü *Sprache* im Fenster oder `ANONYMED_SPRACHE=en` legen sie fest. Berichte und Kommandozeile bleiben deutsch.

## Erster Start

Beim ersten Start legt AnonyMed im Nutzerdatenordner die Pseudonym-Datenbank (`pseudonyme.sqlite`) und daneben den geheimen Schlüssel (`pseudonymschluessel.txt`) an. `anonymed konfig` zeigt die Pfade. **Sichern Sie den Schlüssel.** Mit demselben Schlüssel erzeugt jeder Rechner dieselben Pseudonyme; ohne ihn lassen sich alte Kennungen nicht mehr nachbilden. Die Datenbank enthält die Zuordnung Pseudonym → Klardaten für die Rückersetzung; sie gehört zu den Patientendaten und bleibt auf dem Rechner.

Adressbuch einrichten (einmalig, in der Kommandozeile):

```sh
anonymed kontakte einrichten --url https://ihre-nextcloud.example --benutzer ihrname --adressbuch patienten
```

Das App-Passwort (Nextcloud → Einstellungen → Sicherheit) wird im Schlüsselbund des Systems abgelegt.

## Die acht Schritte

1. **Patient.** Im Adressbuch suchen (Name, Geburtsjahr), eine Patientendatei oder eine vCard laden. Adressbücher richten Sie unter „Adressbücher einrichten …“ ein: eine lokale vCard-Datei oder ein Ordner mit vCard-Dateien (Export aus Apple Kontakte, Thunderbird, Outlook, Nextcloud; bleibt auf dem Rechner) und/oder Nextcloud über CardDAV (Adresse, Benutzer, App-Passwort aus Nextcloud → Sicherheit; das Passwort kommt in den Schlüsselbund, ohne Schlüsselbund in die Konfigurationsdatei). Treffer erscheinen in einer Liste, die erst mit Treffern sichtbar wird; ein Klick übernimmt die Daten in die Felder. „Patientendatei …“ lädt eine JSON- oder TOML-Datei mit den Identifikatoren, wie `anonymed kontakte export` sie schreibt; „Vorlage speichern …“ gibt eine leere zum Ausfüllen. Prüfen Sie die Felder: Alles, was dort steht, wird geschwärzt. Tragen Sie Angehörige, Zuweiser und weitere Begriffe ein (je Zeile einer) oder ziehen Sie eine Textdatei mit einem Eintrag je Zeile auf das Feld; aus den Notizen einer Kontaktkarte werden sie nicht automatisch übernommen. „Patient übernehmen“.
2. **Dokumente.** PDFs, Fotos oder Textdateien (`.txt`, `.md`, `.srt`, `.vtt`, Whisper-`.json`, `.eml`, etwa das Transkript eines mitgeschnittenen Gesprächs oder die E-Mail eines Patienten) hineinziehen; sie werden sofort geöffnet. Fotos und Bilder kommen auf ein Blatt im gewählten Papierformat (A4, A5, A3, US Letter, US Legal oder „wie das Bild“; Hoch- oder Querformat folgt dem Bild, das Bild wird eingepasst). Seiten ohne Textebene (Scans, Fotos) erscheinen darunter zum Aufbereiten vor der Texterkennung, je Seite mit Vorschlag: Schräglage begradigen (vorgeschlagen ab 1,2°, Winkel einstellbar), fotografiertes Blatt entzerren, Hochskalieren 2×, 3× oder 4× (die OCR liest die Seite mit dem Vielfachen der Auflösung, die Seite selbst wird nicht vergrößert gespeichert), Buchstabenmodus (Lanczos-Vergrößerung und geschärfte Striche in Graustufen; eine harte Schwarz-Weiß-Schwelle verschlechterte die Erkennung in Messungen deutlich, deshalb wird er nicht automatisch vorgeschlagen), Hintergrund glätten, Schwarz-Weiß, und unter „Weitere Schritte“: dunkle Ränder säubern, farbige Tinte entfernen (Stempel, Marker, blaue Unterschriften), Entrauschen, Kontrast anheben, Schärfen, Linien entfernen, Ausrichtung erkennen (Hoch-/Querformat aus den Zeilen, Kopfstand per kurzem OCR-Vergleich), Drehen in 90°-Schritten. Auf dem „Nachher“-Bild gezogene Rechtecke löschen den Bereich weiß, bevor die OCR ihn sieht („Gelöschte Bereiche zurückholen“ macht das rückgängig). Entrauschen, Kontrast und Schärfen haben Regler für die Stärke; gelöschte Bereiche holen Sie einzeln mit Cmd/Strg+Z zurück. Links das Original, rechts das Ergebnis mit verschiebbarer Trennlinie, beide Ansichten laufen beim Verschieben (Umschalt oder Option + Ziehen, mittlere Taste) und Zoomen gekoppelt; ein hochskaliertes Ergebnis erscheint in Originalgröße, beim Hineinzoomen zeigt sich der Gewinn. „Schritte auf alle Seiten übertragen“ überträgt die Haken. Ein gelerntes Superresolution-Modell für Text ist nicht enthalten, es bräuchte zusätzliche Bibliotheken und Modelle. „Weiter: Analysieren“.
3. **Texterkennung.** OCR-Programm (RapidOCR mit gebündelten Modellen, Tesseract, aus) und Sprachpakete wählen (Tesseract: `deu+eng`, die installierten Sprachen werden angezeigt; RapidOCR: Sprachtyp `de`, `en`, `latin`). Tesseract hält umrandete Tabellen für Grafik und lässt die Zellen aus (eine Medikamententabelle wurde als ein einziges Wort gelesen); deshalb sucht AnonyMed auf jeder Seite nach Gittern, schneidet sie aus, entfernt die Linien und liest den Ausschnitt in einem zweiten Durchgang als Block; die bessere Lesung gewinnt. Gemessen an synthetischen Tabellen mit dicken Rändern: 0 von 45 Zellwörtern ohne, 42 mit zweitem Durchgang; Seiten ohne Gitter bleiben unberührt. Der Haken „Tabellen“ schaltet das ab. RapidOCR hat das Problem nicht. Mit „Erkannten Text gliedern“ (voreingestellt) erscheint der erkannte Text als Markdown: Zeilen, die bis zum rechten Rand laufen, werden zu Absätzen zusammengefügt (Silbentrennung aufgehoben), ein größerer Abstand beendet den Absatz, Zeilen in größerer Schrift werden Überschriften, kurze fette Zeilen für sich kleine Überschriften, Aufzählungszeichen Listenpunkte, Wörter mit großem Abstand Tabellenzellen (mehrere solche Zeilen eine Markdown-Tabelle). Kursiv wird nicht erkannt, die Programme liefern keine Schräglage. Die Gliederung wird aus der Geometrie der OCR-Zeilen berechnet und gilt für Textdatei, Markdown und den Editor; Sie korrigieren den gegliederten Text. Die unsichtbare Textebene der PDF liegt unabhängig davon Wort für Wort auf den Bildwörtern: Bei korrigiertem oder gegliedertem Text wird jedes Wort dem OCR-Wort zugeordnet, aus dem es stammt (ein korrigiertes Wort bekommt den Kasten des ersetzten, eingefügte Wörter stehen zwischen ihren Nachbarn, Markdown-Zeichen bekommen keinen Kasten), sodass sich Text im PDF-Betrachter genau dort auswählen lässt, wo er gedruckt ist. „Texterkennung starten“ liest alle Dokumente auf Grundlage der aufbereiteten Seiten. Danach steht je Seite das aufbereitete Bild neben dem erkannten Text, den Sie bei OCR-Seiten von Hand korrigieren („Text übernehmen“); Text aus einer Textebene ist nicht veränderbar. Die Korrektur gilt für Textdatei, Markdown und die unsichtbare Textebene; was die OCR im Bild falsch las, schwärzen Sie später mit Kasten oder Maske. „Weiter: Analysieren“.
4. **Analysieren.** Einstellungen der Erkennung: Form des Geburtsdatums, Barcodes, unlesbare Zeilen, Fachbegriffe, unscharfe Suche in Textdateien (weil Spracherkennung Namen so verschreibt wie OCR), NER. Darunter „Empfänger“: Wer für jemand anderen pseudonymisiert (siehe Schlüsselkapseln), gibt hier dessen öffentlichen Schlüssel an. Voreingestellt: Fachbegriffe markieren und schützen, danach NER (sofern das Extra installiert ist). Darunter das Fachvokabular mit seinen Quellen und „Vokabular importieren …“: eine Textdatei mit einem Begriff je Zeile, etwa die beim Export geschriebene `.vokabular.txt`, wird in Ihr Nutzervokabular übernommen und ab der nächsten Analyse geschützt. „Analysieren“ sucht in allen gelesenen Dokumenten und zeigt den Fortschritt; danach öffnet sich der Prüfschritt.
5. **Prüfen.** Hier geht es nur noch um die Anonymisierung; der Text wird nicht mehr bearbeitet. Ampelfarben: Rot wird geschwärzt (gestrichelt, wenn NER oder die unscharfe Suche nur raten), Gelb hat die OCR unsicher gelesen (unlesbare Zeilen werden vorsorglich geschwärzt), Grün bleibt stehen: Fachbegriffe und verworfene Treffer, die sichtbar bleiben und sich per Klick wiederherstellen lassen. Die Quelle jedes Treffers steht in der Tabelle. Ein Fehltreffer (etwa ein Medikamentenname, der wie ein Nachname aussieht): anklicken, „Treffer verwerfen“. Ziehen mit der Maus zeichnet einen Kasten mit dem Ersatztext aus dem Feld neben den Knöpfen; mit „Maske zeichnen“ eine schwarze Maske, unter der Text und Bild verschwinden; Umschalt + Ziehen verschiebt den Ausschnitt, Strg/Cmd + Mausrad zoomt. „Verworfene Treffer für diesen Patienten merken“ speichert Ihre Entscheidungen beim Export in der Pseudonym-Datenbank: Beim nächsten Dokument desselben Patienten ist derselbe Text unter derselben Regel von vornherein grün und lässt sich wiederherstellen. Was die OCR im Bild falsch gelesen hat, schwärzen Sie mit Kasten oder Maske; den Text selbst korrigieren Sie im Schritt Texterkennung. Etwas Übersehenes, zum Beispiel ein handschriftlicher Name: mit der Maus einen Kasten darüber ziehen. Zoom mit Strg/Cmd und Mausrad oder den Knöpfen. Eine Textdatei erscheint statt als Seitenbild als Text mit farbigen Stellen; Klick auf eine Stelle wählt den Treffer, markierter Text wird mit „Auswahl schwärzen“ zum manuellen Treffer. Orange sind dort die Treffer der unscharfen Suche: Vorschläge, die Sie ansehen sollten.
6. **Exportieren.** Beim Öffnen des Schritts läuft zuerst die komplette Abschlussphase in einen Arbeitsordner, samt erneuter Prüfung des Ergebnisses auf alle Angaben aus „1 Patient“. Die Ampel rechts oben zeigt das Ergebnis: Grün heißt nichts mehr gefunden, bereit zum Export; Gelb heißt freigegeben, aber mit Warnungen, die Sie lesen sollten; Rot heißt, es wurden noch Daten gefunden, der Exportknopf bleibt gesperrt, und eine Meldung nennt die Resttreffer, die Sie im Prüfschritt mit Kasten oder Maske nacharbeiten. Der Export kopiert dann die geprüften Dateien. Der Bericht hält fest, was erneut geprüft wurde („Erneut geprüft nach dem Prüfschritt: Name, Geburtsdatum, …“) und welche Treffer Sie bewusst belassen haben; Ihre bewussten Entscheidungen und allgemeine Erinnerungen (Aufbereitungsschritte, OCR-Zusammenfassung, der Hinweis auf nicht erkannte Handschrift, vorsorglich geschwärzte unlesbare Zeilen, NER-Zahlen, unscharfe Treffer, gemerkte Verwerfungen) stehen unter „Hinweise“, nur was Aufmerksamkeit braucht unter „Warnungen“ (Seiten ohne OCR, gewünschtes aber fehlendes NER, unsicherer Patientenabgleich, nicht bestandene Prüfung), und nur diese färben die Ampel gelb; ein bestandener Scan ist grün. Mit „Vokabular der verworfenen Rate-Treffer“ (voreingestellt) entsteht zusätzlich `name_anonym.vokabular.txt`: die im Prüfschritt verworfenen NER- und unscharfen Treffer, ein Begriff je Zeile, für den Import in „4 Analysieren“; verworfene Treffer der festen Regeln bleiben außen vor, ihr Text ist ja ein Identifikator des Patienten. Zielordner wählen. Je Dokument entstehen `name_anonym.pdf` (mit Textebene: bei Scans und Fotos wird der OCR-Text ohne die Treffer unsichtbar eingebettet, auch nach „vollständig rastern“), `name_anonym.txt` (der Text in Lesereihenfolge, das geben Sie dem Sprachmodell), wahlweise `name_anonym.md` und `name_anonym.bericht.json`; aus einer Textdatei wird nur `name_anonym.txt` (gleiche Endung wie die Eingabe, Zeitmarken von Untertiteln bleiben erhalten) und der Bericht. Die Gegenprobe liest das Ergebnis erneut; bleibt ein Identifikator übrig, wird nichts freigegeben und der Bericht sagt warum. Bei OCR-Seiten entstehen Vorschaubilder: Sehen Sie sie an, bevor Sie einen Scan weitergeben.
7. **Rückersetzen.** Den Text des Sprachmodells einfügen, die Person wählen, „Rückersetzen“. Kommt der Text von jemand anderem, öffnen Sie dessen Schlüsselkapsel („Kapsel öffnen …“, siehe unten); dann gilt deren Zuordnung statt der lokalen Datenbank.
8. **Datenbank.** Speicherort von Datenbank und Schlüsseldatei (beide dürfen in beliebigen Ordnern liegen, auch getrennt; beim Wechsel werden die vorhandenen Dateien dorthin kopiert und die alten umbenannt), Statistik der Pseudonym-Datenbank (Patienten, Zuordnungen je Kategorie, gemerkte Verwerfungen, Größe, Integrität, Schlüssel-Kennung) sowie Sichern und Wiederherstellen von allem, was zur Rückersetzung nötig ist: Datenbank und Schlüsseldatei, wahlweise Konfiguration und Nutzervokabular. Die Sicherung ist ein ZIP mit Prüfsummen, mit Passphrase verschlüsselt (`.zip.gpg`, auch `gpg --decrypt` öffnet es) oder auf Wunsch unverschlüsselt. Wiederherstellen ersetzt Datenbank und Schlüssel (die jetzigen werden daneben gesichert) oder führt ein Archiv mit demselben Schlüssel zusammen; zwei verschiedene Schlüssel lassen sich nicht mischen. Solange analysierte Dokumente noch nicht exportiert sind, wird nicht importiert. Kommandozeile: `anonymed datenbank status|exportieren|importieren`. „Herr/Frau Nachname“ setzt die Anrede nach Fall, „voller Name“ den Namen. Verdrehte Pseudonyme (falsches Prüfzeichen) werden gemeldet, mit Vorschlag.

## Texte und Transkripte

Wenn Sie Gespräche aufzeichnen und lokal transkribieren, ist das Transkript eine Textdatei: Sie läuft durch dieselbe Erkennung wie ein PDF, und das Ergebnis ist wieder Text mit Pseudonymen, sonst unverändert. Besonderheiten: Die unscharfe Suche findet den Patientennamen auch verschrieben („Flanz“ statt „Flantz“), verlangt bei Namen und Orten aber einen Großbuchstaben am Anfang; sie kann an Satzanfängen ähnliche Wörter vorschlagen („Land“ für Lang), die Sie im Prüfschritt verwerfen. `--genau` schaltet sie ab. Zahlwörter werden vor dem Abgleich als Ziffern gelesen: „am einundzwanzigsten Juli neunzehnhundertneunundfünfzig“ ist das Geburtsdatum, „Sieringgasse zweiundvierzig“ die Straße, „acht zwei vier sechs zwei“ die Postleitzahl; ersetzt wird dann die ganze Wortfolge.

**Whisper-JSON** (openai-whisper, whisper.cpp, WhisperX) wird zu einer Zeile je Segment mit Zeitmarke und Sprecher aufbereitet und als `.txt` ausgegeben; Wortzeiten und Token-Nummern werden nicht übernommen, denn die Token-Nummern enthalten den Klartext in anderer Form. **E-Mails** (`.eml`, aus dem Mailprogramm gezogen oder exportiert) werden zu Von, An, Cc, Datum, Betreff, dem Textkörper (notfalls aus HTML) und einer Liste der Anhangsnamen; Zustellkopfzeilen wie Message-ID bleiben weg, Anhänge sind nicht enthalten: Ein mitgeschicktes PDF oder Foto anonymisieren Sie als eigene Datei.

## Was geschwärzt wird und was nicht

Geschwärzt: Name in allen Schreibweisen, Geburtsdatum in allen Formaten, Anschrift, Telefon, E-Mail, Versichertennummer, Patienten-ID, Aktenzeichen, eingetragene Angehörige und Zuweiser, Barcodes, sowie generisch jede Versichertennummer, IBAN und E-Mail-Adresse und Werte hinter Etiketten wie „Versicherten-Nr.“ oder „Pat.-ID“.

Nicht geschwärzt: Diagnosen, Medikamente, Messwerte, Befundtexte, Termine. Nicht erkannt werden unbekannte Namen (ein Angehöriger, der nirgends eingetragen ist) und Handschrift, die die OCR nicht als Text findet; dafür gibt es den Prüfschritt.

## NER

Named-Entity-Recognition ist ein statistisches Modell (spaCy, trainiert auf deutschen Nachrichten), das Personen- und Ortsnamen im Fließtext ohne Liste erkennt. Es findet die Angehörige oder den Kollegen, die niemand eingetragen hat, aber es rät: Es kann ein Medikament oder eine Abteilung für eine Person halten und einen Namen übersehen. Deshalb erscheinen seine Treffer im Prüfschritt in eigener Farbe, medizinische Eponyme (Alzheimer, Parkinson, Babinski …) und alles, was das Fachvokabular markiert, sind ausgenommen, gewöhnliche Wörter, die nur am Satzanfang großgeschrieben sind („Überwiesen hat Sie …“), werden verworfen, und es entscheidet nie über die Freigabe. Die Oberfläche schaltet es nach der Fachbegriff-Markierung standardmäßig ein, sobald das Extra installiert ist; auf der Kommandozeile bleibt es Zuwahl (`--ner`). Installation:

```sh
uv sync --extra ner
uv pip install https://github.com/explosion/spacy-models/releases/download/de_core_news_md-3.8.0/de_core_news_md-3.8.0-py3-none-any.whl
```

Gefundene Personen werden zu `Person <Code>`, Orte zu `[Ort <Code>]`, mit demselben Schlüssel-Hash wie die Patientenkennung; derselbe Name bekommt denselben Code, und die Rückersetzung kennt ihn.

## Fachbegriffe: was Rateverfahren nie anfassen dürfen

NER und die unscharfe OCR-Suche laufen hinter einer Schranke: Bevor sie eine Seite ansehen, werden alle medizinischen Fachbegriffe darauf markiert, und diese Stellen sind für beide tabu. Die festen Regeln für die Identifikatoren des Patienten bleiben unberührt (ein Patient, der wirklich Herz heißt, wird weiterhin geschwärzt). Das mitgelieferte Basisvokabular (rund 40 000 deutsche Begriffe) stammt aus Wikidata (CC0): deutsche Bezeichnungen und Synonyme aller Einträge mit ICD-10-Code, ATC-Code, INN oder MeSH-Deskriptor in den medizinischen MeSH-Bäumen (Anatomie, Organismen, Krankheiten, Arzneimittel, Verfahren, Psychiatrie, Phänomene); Geographie und Berufe sind ausgenommen, damit Orte und Nachnamen erkennbar bleiben. Beugungen, Bindestrich-Zusammensetzungen (*Parkinson-Syndrom*) und Umlaut-Umschriften werden erkannt, Mehrwortbegriffe als Ganzes. Eine zweite mitgelieferte Liste (`koerperteile_de.txt`, rund 580 Einträge) enthält Körperteile, Organe, Knochen, Muskeln, Gefäße und Nerven in Alltagsdeutsch sowie Seiten- und Lagewörter (links, rechts, proximal …), weil der Wikidata-Liste viele Alltagsformen fehlen (Kopf, Nacken, Oberbauch, Wade) und NER sie gern für Namen hielt. Eine dritte Liste (`befundbegriffe_de.txt`, rund 370 Einträge) enthält die Begriffe der klinischen Untersuchung und des Befundberichts, wie sie am Zeilenanfang eines Status stehen (Konzentration, Haltung, Gangbild, Strichgang, Nierenlager, Reflexe, Sensibilität, Procedere …), die weder in MeSH noch in der Körperteil-Liste stehen. Zur Reihenfolge: Erst markiert das Vokabular die Seite, dann läuft NER und überspringt jede Entität innerhalb einer markierten Stelle; NER verwirft außerdem einzelne Wörter, die der Tagger als gewöhnliche Substantive einstuft, und unbekannte Einzelwörter (Komposita wie „Nierenlager“) ohne Anrede, Titel oder Präposition davor.

Ihr Nutzervokabular wächst mit jeder Prüfung: Der Export schreibt die verworfenen Rate-Treffer nach `name_anonym.vokabular.txt`, und „Vokabular importieren …“ in „4 Analysieren“ oder `anonymed fachbegriffe ergaenzen DATEI` führt eine solche Datei in `nutzervokabular.txt` im Vokabularordner zusammen (Zusammenführen, nicht Ersetzen). Das Vokabular schützt Begriffe für alle Patienten vor NER und unscharfer Suche; für Treffer der festen Regeln gibt es das Häkchen „Verworfene Treffer für diesen Patienten merken“ im Prüfschritt.

Eigene Listen: `anonymed fachbegriffe importieren DATEI --name NAME` aus MeSH-XML (`--format mesh-xml`, NLM-Datei oder Übersetzung), aus ICD-10-GM, Alpha-ID-SE oder ATC-Tabellen (`--format csv --spalte N`) oder aus jeder einfachen Liste (ein Begriff je Zeile). `anonymed fachbegriffe pruefen WORT` sagt, ob ein Wort geschützt ist, `anonymed fachbegriffe status` zeigt die Quellen. SNOMED CT darf nicht mitgeliefert werden (Lizenz des BfArM nötig); eine lokal lizenzierte Beschreibungsdatei lässt sich wie jede CSV importieren.

## Pseudonyme

Die Hauptperson heißt `Patient K7Q4MX` (Buchstaben und Ziffern aus einem Schlüssel-Hash über Name und Geburtsdatum, mit Prüfzeichen), Angehörige `Angehörige K7Q4MX-1`, Zuweiser `Dr. Z1`, Straßen `[Straße …]`, Orte `[Ort …]` und `[PLZ Ort …]`, das Geburtsdatum `[geb. 1959]` oder `[Alter 66]`. Schreibvarianten desselben Namens ergeben dieselbe Kennung; ähnelt eine Person einem vorhandenen Eintrag nur ungefähr, fragt AnonyMed nach. Einzelheiten: `docs/pseudonyme.md`.

## Schlüsselkapseln: Pseudonyme für einen Empfänger

Patienten und Kolleginnen können Dokumente so pseudonymisieren, dass eine bestimmte Person, etwa die behandelnde Ärztin, sie später im Klartext lesen kann. Dazu veröffentlicht die Empfängerin einen öffentlichen OpenPGP-Schlüssel (auf der Webseite, im Briefkopf). Der Absender gibt AnonyMed diesen Schlüssel in „4 Analysieren“ unter „Empfänger“ (Datei oder https-Adresse, „Schlüssel prüfen“ zeigt den Fingerabdruck, den Sie auf einem zweiten Weg mit dem Empfänger abgleichen; AnonyMed merkt ihn sich und warnt, wenn sich der Schlüssel unter derselben Adresse ändert) und setzt den Haken „Für einen Empfänger pseudonymisieren“. AnonyMed bildet dann alle Pseudonyme aus einem Einmalschlüssel statt aus dem eigenen Geheimnis, schreibt nichts in die lokale Datenbank und legt die Zuordnung zu den Klardaten samt Name, Geburtsdatum und Kennung des Patienten in eine für den Empfänger verschlüsselte Kapsel: `name_anonym.kapsel.asc`. Das pseudonymisierte Dokument und die Antwort des Sprachmodells dürfen wie gewohnt verschickt werden; die Kapsel geht nur an den Empfänger, nie an das Sprachmodell.

Die Empfängerin öffnet die Kapsel in „7 Rückersetzen“ („Kapsel öffnen …“) mit ihrem privaten Schlüssel: aus dem GnuPG-Schlüsselbund (der Agent fragt nach der Passphrase) oder aus einer Schlüsseldatei („Privater Schlüssel“). Danach werden alle Pseudonyme des Absenders zurückgesetzt, auch Angehörige, Zuweiser und Orte, die die eigenen Stammdaten nie kannten; der Patient der Kapsel wird mit der lokalen Pseudonym-Datenbank abgeglichen und der passende Eintrag genannt. Warum eine Kapsel und kein Pseudonym direkt aus dem öffentlichen Schlüssel: Ein Pseudonym, das jeder mit dem öffentlichen Schlüssel nachrechnen kann, ließe sich durch Ausprobieren von Namen und Geburtsdaten auflösen; ein zufälliger Einmalschlüssel, den nur der Empfänger entpacken kann, verrät nichts.

Technik: Das Extra `pgp` bringt pysequoia (Sequoia-PGP) mit, in der Desktop-App enthalten; ein installiertes GnuPG wird genutzt, wenn vorhanden. Curve25519- und RSA-Schlüssel funktionieren; von GnuPG 2.5 exportierte geheime Curve25519-Schlüssel liest pysequoia noch nicht, solche Schlüssel nutzen Sie über den Schlüsselbund. Eigener Schlüssel ohne GnuPG: `anonymed schluessel erzeugen --name … --email …` (öffentlichen Schlüssel veröffentlichen, privaten sicher verwahren; er hat keine Passphrase). Mit GnuPG: `gpg --armor --export <Schlüssel-ID> > anonymed.asc` veröffentlichen, Fingerabdruck mit `gpg --fingerprint <Schlüssel-ID>` daneben. `anonymed schluessel zeigen DATEI|ADRESSE` zeigt Fingerabdruck und Namen eines Schlüssels.

## Kommandozeile

```sh
anonymed anonymisieren befund.pdf --kontakt "Müller 1959"
anonymed anonymisieren scan.pdf --patient patient.json --ocr tesseract --ner
anonymed anonymisieren gespraech.txt --kontakt "Müller 1959"          # Transkript, unscharfe Suche an
anonymed anonymisieren gespraech.srt --patient patient.json --genau   # nur exakte Treffer
anonymed pruefen befund_anonym.pdf --patient patient.json
anonymed rueckersetzen brief.txt --kennung K7Q4MX --form anrede
anonymed anonymisieren foto.jpg --kontakt "Müller 1959" --papier letter   # Bild auf US Letter
anonymed anonymisieren scan.pdf --patient patient.json --roh              # OCR-Text ohne Markdown
anonymed anonymisieren befund.pdf --patient ich.json --empfaenger https://example.org/arzt.asc  # für Empfänger
anonymed rueckersetzen brief.txt --kapsel befund_anonym.kapsel.asc       # Empfängerin, GnuPG-Schlüsselbund
anonymed schluessel erzeugen --name "Dr. Beispiel" --email arzt@example.org  # Schlüsselpaar ohne GnuPG
anonymed kontakte lokal ~/Kontakte/patienten.vcf                         # lokales Adressbuch
anonymed datenbank speicherort --datenbank ~/Sicher/anonymed.sqlite --schluessel ~/Sicher/schluessel.txt
anonymed datenbank status                                                # Statistik
anonymed datenbank exportieren ~/Sicherungen                             # fragt nach einer Passphrase
anonymed datenbank importieren ~/Sicherungen/anonymed_sicherung_2026-11-02_0900.zip.gpg
anonymed fachbegriffe ergaenzen befund_anonym.vokabular.txt           # ins Nutzervokabular
anonymed pseudonyme
anonymed konfig
```

Rückgabewerte: 0 freigegeben, 1 Eingabefehler, 2 nicht freigegeben, 3 Pseudonyme nach der Rückersetzung offen, 4 unsicherer Abgleich (`--gleich KENNUNG` oder `--neu`).
