# PseudonyMed – Anleitung

PseudonyMed schwärzt Patientendokumente auf Ihrem Rechner, bevor Sie sie einem Sprachmodell geben, und setzt die Klardaten anschließend wieder ein. Nichts verlässt den Rechner außer der Suche im eigenen Nextcloud-Adressbuch.

## Installation

**Fertiges Paket:** Archiv für Ihr System entpacken (macOS: `PseudonyMed.app` in den Programme-Ordner ziehen; Windows und Linux: Ordner `PseudonyMed` an einen beliebigen Ort). Darin liegen die Oberfläche `pseudonymed-gui` (macOS: die App) und die Kommandozeile `pseudonymed`. Die Pakete sind nicht signiert; macOS fragt beim ersten Start nach (Rechtsklick → Öffnen), Windows zeigt den SmartScreen-Hinweis.

**Aus dem Quelltext:** Python 3.12 oder neuer und [uv](https://docs.astral.sh/uv/), dann

```sh
uv sync --extra ocr --extra codes --extra gui
uv run pseudonymed gui
```

Tesseract wird als zweites OCR-Programm benutzt, wenn es installiert ist (macOS: `brew install tesseract tesseract-lang`, Ubuntu: `apt install tesseract-ocr tesseract-ocr-deu`); es wird an den üblichen Orten gefunden, auch wenn die App aus dem Finder startet. Nötig ist es nicht, RapidOCR ist enthalten. Wer Tesseract bevorzugt, trägt `backend = "tesseract"` unter `[ocr]` in die Konfigurationsdatei ein (`pseudonymed konfig` zeigt den Pfad) oder setzt `PSEUDONYMED_OCR=tesseract`.

**Sprache.** Die Oberfläche folgt der Systemsprache; `--sprache en` oder `--sprache de` beim Start, das Menü *Sprache* im Fenster oder `PSEUDONYMED_SPRACHE=en` legen sie fest. Berichte und Kommandozeile bleiben deutsch.

## Erster Start

Beim ersten Start legt PseudonyMed im Nutzerdatenordner die Pseudonym-Datenbank (`pseudonyme.sqlite`) und daneben den geheimen Schlüssel (`pseudonymschluessel.txt`) an. `pseudonymed konfig` zeigt die Pfade. **Sichern Sie den Schlüssel.** Mit demselben Schlüssel erzeugt jeder Rechner dieselben Pseudonyme; ohne ihn lassen sich alte Kennungen nicht mehr nachbilden. Die Datenbank enthält die Zuordnung Pseudonym → Klardaten für die Rückersetzung; sie gehört zu den Patientendaten und bleibt auf dem Rechner.

Adressbuch einrichten (einmalig, in der Kommandozeile):

```sh
pseudonymed kontakte einrichten --url https://ihre-nextcloud.example --benutzer ihrname --adressbuch patienten
```

Das App-Passwort (Nextcloud → Einstellungen → Sicherheit) wird im Schlüsselbund des Systems abgelegt.

## Die elf Schritte

1. **Patientendaten.** Im Adressbuch suchen (Name, Geburtsjahr), eine Patientendatei oder eine vCard laden. Adressbücher richten Sie unter „Adressbücher einrichten …“ ein: eine lokale vCard-Datei oder ein Ordner mit vCard-Dateien (Export aus Apple Kontakte, Thunderbird, Outlook, Nextcloud; bleibt auf dem Rechner) und/oder Nextcloud über CardDAV (Adresse, Benutzer, App-Passwort aus Nextcloud → Sicherheit; das Passwort kommt in den Schlüsselbund, ohne Schlüsselbund in die Konfigurationsdatei). Treffer erscheinen in einer Liste, die erst mit Treffern sichtbar wird; ein Klick übernimmt die Daten in die Felder. „Patientendatei …“ lädt eine JSON- oder TOML-Datei mit den Identifikatoren, wie `pseudonymed kontakte export` sie schreibt; „Vorlage speichern …“ gibt eine leere zum Ausfüllen. Prüfen Sie die Felder: Alles, was dort steht, wird geschwärzt. Tragen Sie Angehörige, Zuweiser und weitere Begriffe ein (je Zeile einer) oder ziehen Sie eine Textdatei mit einem Eintrag je Zeile auf das Feld; aus den Notizen einer Kontaktkarte werden sie nicht automatisch übernommen. „Patient übernehmen“.
2. **Identifikatoren.** Was außer den Patientendaten auf eine Person führt und nicht medizinisch ist: Kliniken (Krankenhausverzeichnisse Deutschland und Schweiz, Österreich auf Wunsch über „11 Datenbank“), Berufe (Klassifikation der Berufe 2010), Studienkürzel (ClinicalTrials.gov, DRKS), Titel und Ihre eigenen Einträge (Arbeitgeber, Vereine, Einrichtungen; Klasse „Sonstiges“). Die Tabelle ist gestaltet wie das Fachvokabular: suchen, nach Klasse filtern, Zellen ändern, hinzufügen, löschen, CSV aus- und einlesen. Wie die Patientendaten werden Identifikatoren standardmäßig geschwärzt (Platzhalter wie `[Klinik 7HQ2NB]`, `[Beruf …]`, in der Sichtprüfung gestrichelt und verwerfbar), aber nur mit Kontext: Kliniknamen überall (amtlicher Name, sein Hauptteil oder „Klinikum, Krankenhaus … + Ort“ für Orte mit Krankenhaus), Berufe nur neben Hinweisen wie „arbeitet als“, „gelernter“, „ist“, „von Beruf“ oder in der Sozialanamnese, Studienkürzel nur in der registrierten Schreibweise neben „Studie“ (Registernummern wie NCT oder DRKS immer), Titel nur direkt vor oder nach einem erkannten Namen, eigene Einträge überall. Der Erwerbsstatus (berentet, arbeitslos) bleibt nach der GeMTeX-Leitlinie stehen. Gelöschte mitgelieferte Einträge bleiben auch nach Updates gelöscht, bis Sie sie wiederherstellen; geänderte werden zu eigenen. Der Haken in „6 Analyse“ schaltet die Schwärzung ab.
3. **Fachvokabular.** Alle Begriffe, die NER und die unscharfe Suche nie schwärzen dürfen, als sortierbare Tabelle (Begriff, Kategorie, angelegt) aus der Pseudonym-Datenbank: die mitgelieferten Listen (Medizin aus Wikidata, Körperteile, Befundbegriffe, Eponyme) werden beim ersten Start in die Tabelle geladen, frühere eigene Listen aus dem Ordner `fachbegriffe/` einmalig übernommen. Suchen, nach Spalte sortieren (Spaltenkopf), Zellen per Doppelklick ändern, Begriffe hinzufügen und löschen (auch mitgelieferte, etwa „Wolf“), als CSV exportieren und CSV oder Listen (ein Begriff je Zeile, etwa die beim Export geschriebene `.vokabular.txt`) importieren; „Mitgelieferte Listen erneut einspielen“ holt gelöschte Grundbegriffe zurück. Kommandozeile: `pseudonymed fachbegriffe status|hinzufuegen|entfernen|exportieren|importieren|ergaenzen`.
4. **Dokumente.** PDFs, Fotos oder Textdateien (`.txt`, `.md`, `.srt`, `.vtt`, Whisper-`.json`, `.eml`, etwa das Transkript eines mitgeschnittenen Gesprächs oder die E-Mail eines Patienten) hineinziehen; sie werden sofort geöffnet. Ein in der Sichtprüfung gespeicherter Arbeitsstand (`name.arbeitsstand.json` oder das Dokument `name.arbeitsstand.pdf` daneben) füllt alles bis einschließlich „7 Sichtprüfung“ wieder aus: Patientendaten, Aufbereitung, Texterkennung samt Korrekturen, Treffer, verworfene Treffer, Kästen, Masken und Aufnahmen; die Oberfläche springt gleich zur Sichtprüfung. Fotos und Bilder kommen auf ein Blatt im gewählten Papierformat (A4, A5, A3, US Letter, US Legal oder „wie das Bild“; Hoch- oder Querformat folgt dem Bild, das Bild wird eingepasst). Seiten ohne Textebene (Scans, Fotos) erscheinen darunter zum Aufbereiten vor der Texterkennung, je Seite mit Vorschlag: Schräglage begradigen (vorgeschlagen ab 1,2°, Winkel einstellbar), fotografiertes Blatt entzerren, Hochskalieren 2×, 3× oder 4× (die OCR liest die Seite mit dem Vielfachen der Auflösung, die Seite selbst wird nicht vergrößert gespeichert), Buchstabenmodus (Lanczos-Vergrößerung und geschärfte Striche in Graustufen; eine harte Schwarz-Weiß-Schwelle verschlechterte die Erkennung in Messungen deutlich, deshalb wird er nicht automatisch vorgeschlagen), Hintergrund glätten, Schwarz-Weiß, und unter „Weitere Schritte“: dunkle Ränder säubern, farbige Tinte entfernen (Stempel, Marker, blaue Unterschriften), Entrauschen, Kontrast anheben, Schärfen, Linien entfernen, Ausrichtung erkennen (Hoch-/Querformat aus den Zeilen, Kopfstand per kurzem OCR-Vergleich), Drehen in 90°-Schritten. Auf dem „Nachher“-Bild gezogene Rechtecke löschen den Bereich weiß, bevor die OCR ihn sieht („Gelöschte Bereiche zurückholen“ macht das rückgängig). Entrauschen, Kontrast und Schärfen haben Regler für die Stärke; gelöschte Bereiche holen Sie einzeln mit Cmd/Strg+Z zurück. Links das Original, rechts das Ergebnis mit verschiebbarer Trennlinie, beide Ansichten laufen beim Verschieben (Umschalt oder Option + Ziehen, mittlere Taste) und Zoomen gekoppelt; ein hochskaliertes Ergebnis erscheint in Originalgröße, beim Hineinzoomen zeigt sich der Gewinn. „Schritte auf alle Seiten übertragen“ überträgt die Haken. Ein gelerntes Superresolution-Modell für Text ist nicht enthalten, es bräuchte zusätzliche Bibliotheken und Modelle. „Weiter: Analysieren“.
5. **Texterkennung.** OCR-Programm (RapidOCR mit gebündelten Modellen, Tesseract, aus) und Sprachpakete wählen (Tesseract: `deu+eng`, die installierten Sprachen werden angezeigt; RapidOCR: Sprachtyp `de`, `en`, `latin`). Tesseract hält umrandete Tabellen für Grafik und lässt die Zellen aus (eine Medikamententabelle wurde als ein einziges Wort gelesen); deshalb sucht PseudonyMed auf jeder Seite nach Gittern, schneidet sie aus, entfernt die Linien und liest den Ausschnitt in einem zweiten Durchgang als Block; die bessere Lesung gewinnt. Gemessen an synthetischen Tabellen mit dicken Rändern: 0 von 45 Zellwörtern ohne, 42 mit zweitem Durchgang; Seiten ohne Gitter bleiben unberührt. Der Haken „Tabellen“ schaltet das ab. RapidOCR hat das Problem nicht. Mit „Erkannten Text gliedern“ (voreingestellt) erscheint der erkannte Text als Markdown: Zeilen, die bis zum rechten Rand laufen, werden zu Absätzen zusammengefügt (Silbentrennung aufgehoben), ein größerer Abstand beendet den Absatz, Zeilen in größerer Schrift werden Überschriften, kurze fette Zeilen für sich kleine Überschriften, Aufzählungszeichen Listenpunkte, Wörter mit großem Abstand Tabellenzellen (mehrere solche Zeilen eine Markdown-Tabelle). Kursiv wird nicht erkannt, die Programme liefern keine Schräglage. Die Gliederung wird aus der Geometrie der OCR-Zeilen berechnet und gilt für Textdatei, Markdown und den Editor; Sie korrigieren den gegliederten Text. Die unsichtbare Textebene der PDF liegt unabhängig davon Wort für Wort auf den Bildwörtern: Bei korrigiertem oder gegliedertem Text wird jedes Wort dem OCR-Wort zugeordnet, aus dem es stammt (ein korrigiertes Wort bekommt den Kasten des ersetzten, eingefügte Wörter stehen zwischen ihren Nachbarn, Markdown-Zeichen bekommen keinen Kasten), sodass sich Text im PDF-Betrachter genau dort auswählen lässt, wo er gedruckt ist. „Texterkennung starten“ liest alle Dokumente auf Grundlage der aufbereiteten Seiten. Danach steht je Seite das aufbereitete Bild neben dem erkannten Text, den Sie bei OCR-Seiten von Hand korrigieren („Text übernehmen“); Text aus einer Textebene ist nicht veränderbar. Die Korrektur gilt für Textdatei, Markdown und die unsichtbare Textebene; was die OCR im Bild falsch las, schwärzen Sie später mit Kasten oder Maske. „Weiter: Analysieren“.
6. **Analyse.** „Analysieren“ durchsucht neue Dokumente, „Erneut analysieren“ auch schon analysierte mit den jetzigen Einstellungen: Aufbereitung, Texterkennung und Korrekturen bleiben, Kästen, Masken, Aufnahmen und verworfene Treffer werden übernommen. So entstehen Varianten desselben Dokuments, ohne von vorn zu beginnen. Einstellungen der Erkennung: Form des Geburtsdatums, Barcodes, unlesbare Zeilen, Fachbegriffe, unscharfe Suche in Textdateien (weil Spracherkennung Namen so verschreibt wie OCR), NER, dazu vier Optionen für den medizinischen Inhalt, alle standardmäßig aus, weil Medikamente und Laborwerte zum Inhalt gehören: „Medikamente: Substanz schwärzen“ ersetzt den Namen aus dem Lexikon durch `[Medikament …]` (Namen, die zugleich eine Erkrankung bezeichnen, etwa „ASS“, bleiben); „Medikamente: Dosierung und Verordnungsschema schwärzen“ ersetzt, was neben einer Substanz steht, durch `[Dosierung …]` („500 mg 1-0-1“, „2 Tbl.“, „bei Bedarf“, „p. o.“), die Substanz bleibt, wenn sie nicht eigens gewählt ist; „Laborwerte: Untersuchung schwärzen“ ersetzt den Namen der Untersuchung, wo immer er steht, durch `[Laborwert …]`; „Laborwerte: Messwert schwärzen“ ersetzt den Wert hinter einer Untersuchung durch `[Messwert …]` („2,3 mU/l“, „< 5 mg/l“). Die vier Stufen sind unabhängig: Nur die Substanz zu kennen ist etwas anderes als auch Dosis und Schema, nur die Untersuchung etwas anderes als auch den Messwert. Ein Begriff auf beiden Listen („Kalium“) ist mit Messwert dahinter ein Laborwert, mit Dosis ein Medikament. Handelsnamen, die das Lexikon nicht kennt (etwa Marcumar), tragen Sie in „3 Fachvokabular“ mit der Kategorie „Medikament“ ein, eigene Labornamen mit der Kategorie „Laborwert“. Die Reidentifikation setzt alles wieder ein. Darunter die Statistik des Fachvokabulars (bearbeitet wird es in „3 Fachvokabular“) und „Empfänger“: Wer für jemand anderen pseudonymisiert (siehe Schlüsselkapseln), gibt hier dessen öffentlichen Schlüssel an. Voreingestellt: Fachbegriffe markieren und schützen, danach NER (sofern das Extra installiert ist). Darunter das Fachvokabular mit seinen Quellen und „Vokabular importieren …“: eine Textdatei mit einem Begriff je Zeile, etwa die beim Export geschriebene `.vokabular.txt`, wird in Ihr Nutzervokabular übernommen und ab der nächsten Analyse geschützt. „Analysieren“ sucht in allen gelesenen Dokumenten und zeigt den Fortschritt; danach öffnet sich der Prüfschritt.
7. **Sichtprüfung.** Hier geht es nur noch um die Pseudonymisierung; der Text wird nicht mehr bearbeitet. Ampelfarben: Rot wird geschwärzt (gestrichelt, wenn NER oder die unscharfe Suche nur raten), Gelb hat die OCR unsicher gelesen (unlesbare Zeilen werden vorsorglich geschwärzt), Grün bleibt stehen: Fachbegriffe und verworfene Treffer, die sichtbar bleiben und sich per Klick wiederherstellen lassen. Die Quelle jedes Treffers steht in der Tabelle. Ein Fehltreffer (etwa ein Medikamentenname, der wie ein Nachname aussieht): anklicken, „Treffer verwerfen“. Ziehen mit der Maus zeichnet einen Kasten mit dem Ersatztext aus dem Feld neben den Knöpfen; mit „Maske zeichnen“ eine schwarze Maske, unter der Text und Bild verschwinden; Umschalt + Ziehen verschiebt den Ausschnitt, Strg/Cmd + Mausrad zoomt. „Verworfene Treffer für diesen Patienten merken“ speichert Ihre Entscheidungen beim Export in der Pseudonym-Datenbank: Beim nächsten Dokument desselben Patienten ist derselbe Text unter derselben Regel von vornherein grün und lässt sich wiederherstellen. Was die OCR im Bild falsch gelesen hat, schwärzen Sie mit Kasten oder Maske; den Text selbst korrigieren Sie im Schritt Texterkennung. Etwas Übersehenes, zum Beispiel ein handschriftlicher Name: mit der Maus einen Kasten darüber ziehen. Zoom mit Strg/Cmd und Mausrad oder den Knöpfen. Etwas, das die Analyse nicht gefunden hat oder das als Fachbegriff grün stehen bleibt, kommt mit einem Klick auf das Wort (blau) und „Auswahl aufnehmen“ in die Liste; Strg/Cmd + Klick erweitert die Auswahl bis zum angeklickten Wort. Bleibt im Feld „Ersatztext“ das voreingestellte „[geschwärzt]“ stehen, bekommt das aufgenommene Wort einen eigenen Code `[Begriff …]`, den die Reidentifikation zurücksetzt; sonst den eingetragenen Text. „Arbeitsstand speichern …“ schreibt das aufbereitete Dokument (`name.arbeitsstand.pdf`) und eine Konfigurationsdatei (`name.arbeitsstand.json`) mit allem, was bis hierher entstanden ist; beide enthalten Klardaten und gehören verwahrt wie das Original. Über „4 Dokumente“ wieder hereingezogen, lässt sich die Sichtprüfung fortsetzen oder abwandeln. Eine Textdatei erscheint statt als Seitenbild als Text mit farbigen Stellen; Klick auf eine Stelle wählt den Treffer, markierter Text wird mit „Auswahl schwärzen“ zum manuellen Treffer. Orange sind dort die Treffer der unscharfen Suche: Vorschläge, die Sie ansehen sollten.
8. **Kontrolle.** Zwei Ampeln vor dem Export. Die erste ist die erneute Prüfung: Die komplette Abschlussphase läuft in einen Arbeitsordner, und das Ergebnis wird auf alle Angaben aus „1 Patientendaten“ durchsucht; Rot heißt, es wurde noch etwas gefunden, dann nacharbeiten. Die zweite ist das Restrisiko: eine Schätzung, wie viele Menschen das teilen, was im Text noch steht. Sie folgt dem k-map-Prinzip der Risikobewertung (El Emam, EMA Policy 0070 mit der Schwelle 0,09, Rocher et al. 2019): Geschlecht (1 Bit), Geburtsjahr oder Alter (etwa 6,4 Bit), der kleinste genannte Ort nach Einwohnerzahl (Destatis-Gemeindeverzeichnis) und die seltenste genannte seltene Erkrankung nach Orphanet-Prävalenz werden in Bit umgerechnet; etwa 26,3 Bit genügen, um in Deutschland eine Person herauszugreifen. λ ist die erwartete Zahl gleichartiger Personen, κ die Wahrscheinlichkeit, dass ein Treffer die richtige Person ist. Grün ab λ = 11 (κ ≤ 0,09), Gelb ab 5, Rot darunter. Markierungen nennen, was das Modell nicht wiegen kann: Alter ab 90, Geburtsjahr und Alter neben exakten Daten, datierte berichtbare Ereignisse, Beruf, Familienkonstellation, Ortsnamen von Gemeinden unter 20.000 Einwohnern. Alle Dokumente desselben Patienten werden zusammen bewertet, auch früher freigegebene (gemerkt werden nur Kategorien und Gewichte, keine Klardaten). Referenzpopulation (Deutschland oder das Einzugsgebiet der Sprechstunde) und eigene Orte (Sprechstunde, Klinik) sind einstellbar. Die Schätzung ist eine eigene Synthese aus veröffentlichten Bausteinen, kein Standard, und nimmt Unabhängigkeit der Merkmale an, was bei untypischen Kombinationen zu optimistisch ist; sie lenkt die Sichtprüfung auf das Detail mit dem größten Beitrag. Rot sperrt den Export nicht, verlangt aber eine ausdrückliche Bestätigung.
9. **Export.** Die Ampeln aus „8 Kontrolle“ (erneute Prüfung und Restrisiko) stehen hier noch einmal; wer den Schritt übersprungen hat, bekommt die erneute Prüfung beim Öffnen nachgeholt. Die erste Ampel zeigt das Ergebnis: Grün heißt nichts mehr gefunden, bereit zum Export; Gelb heißt freigegeben, aber mit Warnungen, die Sie lesen sollten; Rot heißt, es wurden noch Daten gefunden, der Exportknopf bleibt gesperrt, und eine Meldung nennt die Resttreffer, die Sie im Prüfschritt mit Kasten oder Maske nacharbeiten. Der Export kopiert dann die geprüften Dateien. Der Bericht hält fest, was erneut geprüft wurde („Erneut geprüft nach dem Prüfschritt: Name, Geburtsdatum, …“) und welche Treffer Sie bewusst belassen haben; Ihre bewussten Entscheidungen und allgemeine Erinnerungen (Aufbereitungsschritte, OCR-Zusammenfassung, der Hinweis auf nicht erkannte Handschrift, vorsorglich geschwärzte unlesbare Zeilen, NER-Zahlen, unscharfe Treffer, gemerkte Verwerfungen) stehen unter „Hinweise“, nur was Aufmerksamkeit braucht unter „Warnungen“ (Seiten ohne OCR, gewünschtes aber fehlendes NER, unsicherer Patientenabgleich, nicht bestandene Prüfung), und nur diese färben die Ampel gelb; ein bestandener Scan ist grün. Mit „Vokabular der verworfenen Rate-Treffer“ (voreingestellt) entsteht zusätzlich `name_pseudonym.vokabular.txt`: die im Prüfschritt verworfenen NER- und unscharfen Treffer, ein Begriff je Zeile, für den Import in „3 Fachvokabular“; verworfene Treffer der festen Regeln bleiben außen vor, ihr Text ist ja ein Identifikator des Patienten. Zielordner wählen. Je Dokument entstehen `name_pseudonym.pdf` (mit Textebene: bei Scans und Fotos wird der OCR-Text ohne die Treffer unsichtbar eingebettet, auch nach „vollständig rastern“), `name_pseudonym.txt` (der Text in Lesereihenfolge, das geben Sie dem Sprachmodell), wahlweise `name_pseudonym.md` und `name_pseudonym.bericht.json`; aus einer Textdatei wird nur `name_pseudonym.txt` (gleiche Endung wie die Eingabe, Zeitmarken von Untertiteln bleiben erhalten) und der Bericht. Die Gegenprobe liest das Ergebnis erneut; bleibt ein Identifikator übrig, wird nichts freigegeben und der Bericht sagt warum. Bei OCR-Seiten entstehen Vorschaubilder: Sehen Sie sie an, bevor Sie einen Scan weitergeben.
10. **Reidentifikation.** Den Text des Sprachmodells einfügen, die Person wählen, „Rückersetzen“. Kommt der Text von jemand anderem, öffnen Sie dessen Schlüsselkapsel („Kapsel öffnen …“, siehe unten); dann gilt deren Zuordnung statt der lokalen Datenbank.
11. **Datenbank.** Speicherort von Datenbank und Schlüsseldatei (beide dürfen in beliebigen Ordnern liegen, auch getrennt; beim Wechsel werden die vorhandenen Dateien dorthin kopiert und die alten umbenannt), Statistik der Pseudonym-Datenbank (Patienten, Zuordnungen je Kategorie, gemerkte Verwerfungen, Größe, Integrität, Schlüssel-Kennung) sowie Sichern und Wiederherstellen von allem, was zur Rückersetzung nötig ist: Datenbank und Schlüsseldatei, wahlweise Konfiguration und Nutzervokabular. Die Sicherung ist ein ZIP mit Prüfsummen, mit Passphrase verschlüsselt (`.zip.gpg`, auch `gpg --decrypt` öffnet es) oder auf Wunsch unverschlüsselt. Wiederherstellen ersetzt Datenbank und Schlüssel (die jetzigen werden daneben gesichert) oder führt ein Archiv mit demselben Schlüssel zusammen; zwei verschiedene Schlüssel lassen sich nicht mischen. Solange analysierte Dokumente noch nicht exportiert sind, wird nicht importiert. Unter „Zusatzdaten“ lädt „Beim Ministerium laden“ die aktuelle Liste der Krankenanstalten in Österreich direkt vom Sozialministerium in Ihre lokale Datenbank (oder „Aus Datei …“ eine selbst heruntergeladene Mappe); PseudonyMed liefert sie nicht mit, weil das Ministerium den Nachdruck nur zu nichtkommerziellen Zwecken gestattet. Kommandozeile: `pseudonymed datenbank status|exportieren|importieren|zusatzdaten kliniken-at`. „Herr/Frau Nachname“ setzt die Anrede nach Fall, „voller Name“ den Namen. Verdrehte Pseudonyme (falsches Prüfzeichen) werden gemeldet, mit Vorschlag.

## Texte und Transkripte

Wenn Sie Gespräche aufzeichnen und lokal transkribieren, ist das Transkript eine Textdatei: Sie läuft durch dieselbe Erkennung wie ein PDF, und das Ergebnis ist wieder Text mit Pseudonymen, sonst unverändert. Besonderheiten: Die unscharfe Suche findet den Patientennamen auch verschrieben („Flanz“ statt „Flantz“), verlangt bei Namen und Orten aber einen Großbuchstaben am Anfang; sie kann an Satzanfängen ähnliche Wörter vorschlagen („Land“ für Lang), die Sie im Prüfschritt verwerfen. `--genau` schaltet sie ab. Zahlwörter werden vor dem Abgleich als Ziffern gelesen: „am einundzwanzigsten Juli neunzehnhundertneunundfünfzig“ ist das Geburtsdatum, „Sieringgasse zweiundvierzig“ die Straße, „acht zwei vier sechs zwei“ die Postleitzahl; ersetzt wird dann die ganze Wortfolge.

**Whisper-JSON** (openai-whisper, whisper.cpp, WhisperX) wird zu einer Zeile je Segment mit Zeitmarke und Sprecher aufbereitet und als `.txt` ausgegeben; Wortzeiten und Token-Nummern werden nicht übernommen, denn die Token-Nummern enthalten den Klartext in anderer Form. **E-Mails** (`.eml`, aus dem Mailprogramm gezogen oder exportiert) werden zu Von, An, Cc, Datum, Betreff, dem Textkörper (notfalls aus HTML) und einer Liste der Anhangsnamen; Zustellkopfzeilen wie Message-ID bleiben weg, Anhänge sind nicht enthalten: Ein mitgeschicktes PDF oder Foto pseudonymisieren Sie als eigene Datei.

## Was geschwärzt wird und was nicht

Geschwärzt: Name in allen Schreibweisen, Geburtsdatum in allen Formaten, Anschrift, Telefon, E-Mail, Versichertennummer, Patienten-ID, Aktenzeichen, eingetragene Angehörige und Zuweiser, Barcodes, sowie generisch jede Versichertennummer, IBAN und E-Mail-Adresse und Werte hinter Etiketten wie „Versicherten-Nr.“ oder „Pat.-ID“.

Standardmäßig geschwärzt, aber in der Sichtprüfung verwerfbar: Identifikatoren aus „2 Identifikatoren“ (Kliniken, Berufe mit Kontext, Studien, Titel an Namen).

Nicht geschwärzt: Diagnosen, Medikamente und Laborwerte (auf Wunsch in vier Stufen: Substanz, Dosierung, Untersuchung, Messwert; siehe „6 Analyse“), Messwerte, Befundtexte, Termine, Erwerbsstatus. Nicht erkannt werden unbekannte Namen (ein Angehöriger, der nirgends eingetragen ist) und Handschrift, die die OCR nicht als Text findet; dafür gibt es den Prüfschritt.

## NER

Named-Entity-Recognition ist ein statistisches Modell (spaCy, trainiert auf deutschen Nachrichten), das Personen- und Ortsnamen im Fließtext ohne Liste erkennt. Es findet die Angehörige oder den Kollegen, die niemand eingetragen hat, aber es rät: Es kann ein Medikament oder eine Abteilung für eine Person halten und einen Namen übersehen. Deshalb erscheinen seine Treffer im Prüfschritt in eigener Farbe, medizinische Eponyme (Alzheimer, Parkinson, Babinski …) und alles, was das Fachvokabular markiert, sind ausgenommen, gewöhnliche Wörter, die nur am Satzanfang großgeschrieben sind („Überwiesen hat Sie …“), werden verworfen, und es entscheidet nie über die Freigabe. Die Oberfläche schaltet es nach der Fachbegriff-Markierung standardmäßig ein, sobald das Extra installiert ist; auf der Kommandozeile bleibt es Zuwahl (`--ner`). Installation:

```sh
uv sync --extra ner
uv pip install https://github.com/explosion/spacy-models/releases/download/de_core_news_md-3.8.0/de_core_news_md-3.8.0-py3-none-any.whl
```

Gefundene Personen werden zu `Person <Code>`, Orte zu `[Ort <Code>]`, mit demselben Schlüssel-Hash wie die Patientenkennung; derselbe Name bekommt denselben Code, und die Rückersetzung kennt ihn.

## Fachbegriffe: was Rateverfahren nie anfassen dürfen

NER und die unscharfe OCR-Suche laufen hinter einer Schranke: Bevor sie eine Seite ansehen, werden alle medizinischen Fachbegriffe darauf markiert, und diese Stellen sind für beide tabu. Die festen Regeln für die Identifikatoren des Patienten bleiben unberührt (ein Patient, der wirklich Herz heißt, wird weiterhin geschwärzt). Das mitgelieferte Basisvokabular (rund 40 000 deutsche Begriffe) stammt aus Wikidata (CC0): deutsche Bezeichnungen und Synonyme aller Einträge mit ICD-10-Code, ATC-Code, INN oder MeSH-Deskriptor in den medizinischen MeSH-Bäumen (Anatomie, Organismen, Krankheiten, Arzneimittel, Verfahren, Psychiatrie, Phänomene); Geographie und Berufe sind ausgenommen, damit Orte und Nachnamen erkennbar bleiben. Beugungen, Bindestrich-Zusammensetzungen (*Parkinson-Syndrom*) und Umlaut-Umschriften werden erkannt, Mehrwortbegriffe als Ganzes. Eine zweite mitgelieferte Liste (`koerperteile_de.txt`, rund 580 Einträge) enthält Körperteile, Organe, Knochen, Muskeln, Gefäße und Nerven in Alltagsdeutsch sowie Seiten- und Lagewörter (links, rechts, proximal …), weil der Wikidata-Liste viele Alltagsformen fehlen (Kopf, Nacken, Oberbauch, Wade) und NER sie gern für Namen hielt. Eine dritte Liste (`befundbegriffe_de.txt`, rund 370 Einträge) enthält die Begriffe der klinischen Untersuchung und des Befundberichts, wie sie am Zeilenanfang eines Status stehen (Konzentration, Haltung, Gangbild, Strichgang, Nierenlager, Reflexe, Sensibilität, Procedere …), die weder in MeSH noch in der Körperteil-Liste stehen. Zur Reihenfolge: Erst markiert das Vokabular die Seite, dann läuft NER und überspringt jede Entität innerhalb einer markierten Stelle; NER verwirft außerdem einzelne Wörter, die der Tagger als gewöhnliche Substantive einstuft, und unbekannte Einzelwörter (Komposita wie „Nierenlager“) ohne Anrede, Titel oder Präposition davor.

Ihr Nutzervokabular wächst mit jeder Prüfung: Der Export schreibt die verworfenen Rate-Treffer nach `name_pseudonym.vokabular.txt`, und „CSV oder Liste importieren …“ in „3 Fachvokabular“ oder `pseudonymed fachbegriffe ergaenzen DATEI` übernimmt eine solche Datei in die Tabelle (Kategorie „Nutzervokabular“). Das Vokabular schützt Begriffe für alle Patienten vor NER und unscharfer Suche; für Treffer der festen Regeln gibt es das Häkchen „Verworfene Treffer für diesen Patienten merken“ im Prüfschritt.

Eigene Listen: `pseudonymed fachbegriffe importieren DATEI --name KATEGORIE` aus MeSH-XML (`--format mesh-xml`, NLM-Datei oder Übersetzung), aus ICD-10-GM, Alpha-ID-SE oder ATC-Tabellen (`--format csv --spalte N`) oder aus jeder einfachen Liste (ein Begriff je Zeile); alles landet in der Tabelle `vokabular` der Pseudonym-Datenbank und damit in jeder Sicherung. `pseudonymed fachbegriffe pruefen WORT` sagt, ob ein Wort geschützt ist, `pseudonymed fachbegriffe status` zeigt die Kategorien. SNOMED CT darf nicht mitgeliefert werden (Lizenz des BfArM nötig); eine lokal lizenzierte Beschreibungsdatei lässt sich wie jede CSV importieren.

## Pseudonyme

Die Hauptperson heißt `Patient K7Q4MX` (Buchstaben und Ziffern aus einem Schlüssel-Hash über Name und Geburtsdatum, mit Prüfzeichen), Angehörige `Angehörige K7Q4MX-1`, Zuweiser `Dr. Z1`, Straßen `[Straße …]`, Orte `[Ort …]` und `[PLZ Ort …]`, das Geburtsdatum `[geb. 1959]` oder `[Alter 66]`. Schreibvarianten desselben Namens ergeben dieselbe Kennung; ähnelt eine Person einem vorhandenen Eintrag nur ungefähr, fragt PseudonyMed nach. Einzelheiten: `docs/pseudonyme.md`.

## Schlüsselkapseln: Pseudonyme für einen Empfänger

Patienten und Kolleginnen können Dokumente so pseudonymisieren, dass eine bestimmte Person, etwa die behandelnde Ärztin, sie später im Klartext lesen kann. Dazu veröffentlicht die Empfängerin einen öffentlichen OpenPGP-Schlüssel (auf der Webseite, im Briefkopf). Der Absender gibt PseudonyMed diesen Schlüssel in „5 Analysieren“ unter „Empfänger“ (Datei oder https-Adresse, „Schlüssel prüfen“ zeigt den Fingerabdruck, den Sie auf einem zweiten Weg mit dem Empfänger abgleichen; PseudonyMed merkt ihn sich und warnt, wenn sich der Schlüssel unter derselben Adresse ändert) und setzt den Haken „Für einen Empfänger pseudonymisieren“. PseudonyMed bildet dann alle Pseudonyme aus einem Einmalschlüssel statt aus dem eigenen Geheimnis, schreibt nichts in die lokale Datenbank und legt die Zuordnung zu den Klardaten samt Name, Geburtsdatum und Kennung des Patienten in eine für den Empfänger verschlüsselte Kapsel: `name_pseudonym.kapsel.asc`. Das pseudonymisierte Dokument und die Antwort des Sprachmodells dürfen wie gewohnt verschickt werden; die Kapsel geht nur an den Empfänger, nie an das Sprachmodell.

Die Empfängerin öffnet die Kapsel in „10 Reidentifikation“ („Kapsel öffnen …“) mit ihrem privaten Schlüssel: aus dem GnuPG-Schlüsselbund (der Agent fragt nach der Passphrase) oder aus einer Schlüsseldatei („Privater Schlüssel“). Danach werden alle Pseudonyme des Absenders zurückgesetzt, auch Angehörige, Zuweiser und Orte, die die eigenen Stammdaten nie kannten; der Patient der Kapsel wird mit der lokalen Pseudonym-Datenbank abgeglichen und der passende Eintrag genannt. Warum eine Kapsel und kein Pseudonym direkt aus dem öffentlichen Schlüssel: Ein Pseudonym, das jeder mit dem öffentlichen Schlüssel nachrechnen kann, ließe sich durch Ausprobieren von Namen und Geburtsdaten auflösen; ein zufälliger Einmalschlüssel, den nur der Empfänger entpacken kann, verrät nichts.

Technik: Das Extra `pgp` bringt pysequoia (Sequoia-PGP) mit, in der Desktop-App enthalten; ein installiertes GnuPG wird genutzt, wenn vorhanden. Curve25519- und RSA-Schlüssel funktionieren; von GnuPG 2.5 exportierte geheime Curve25519-Schlüssel liest pysequoia noch nicht, solche Schlüssel nutzen Sie über den Schlüsselbund. Eigener Schlüssel ohne GnuPG: `pseudonymed schluessel erzeugen --name … --email …` (öffentlichen Schlüssel veröffentlichen, privaten sicher verwahren; er hat keine Passphrase). Mit GnuPG: `gpg --armor --export <Schlüssel-ID> > pseudonymed.asc` veröffentlichen, Fingerabdruck mit `gpg --fingerprint <Schlüssel-ID>` daneben. `pseudonymed schluessel zeigen DATEI|ADRESSE` zeigt Fingerabdruck und Namen eines Schlüssels.

## Arbeitsstand: Varianten desselben Dokuments

Aufbereitung, Texterkennung und Sichtprüfung kosten Zeit und Urteil. „Arbeitsstand speichern …“ in der Sichtprüfung hält alles fest: `name.arbeitsstand.pdf` ist das aufbereitete Dokument im Klartext (bei Textdateien `name.arbeitsstand.txt`, `.srt` …), `name.arbeitsstand.json` enthält Patientendaten, Einstellungen, Aufbereitungsplan, jede Seite mit Textebene und OCR-Wörtern samt Kästen, den korrigierten OCR-Text, die Treffer mit ihren Pseudonymen, verworfene Treffer, Kästen, Masken und Aufnahmen. Beide Dateien enthalten Klardaten; sie gehören dorthin, wo auch das Original liegt. Eine der beiden auf „4 Dokumente“ ziehen, und die Sichtprüfung steht wieder da, wie sie gespeichert wurde, ohne erneute OCR; die Patientendaten sind übernommen. Dort lässt sich anders entscheiden (Treffer verwerfen oder wiederherstellen, Wörter aufnehmen), und „Erneut analysieren“ in „6 Analyse“ durchsucht das Dokument mit anderen Einstellungen (etwa Medikamente schwärzen, NER aus), wobei Kästen, Masken, Aufnahmen und verworfene Treffer erhalten bleiben. Jede Variante lässt sich wieder als Arbeitsstand speichern. Im Empfängermodus (Einmalschlüssel) gibt es keinen Arbeitsstand, weil die Codes nicht wiederherstellbar wären. Auf der Kommandozeile schreibt `--arbeitsstand` den Stand neben die Ausgabe, und ein `name.arbeitsstand.json` als Eingabe wird abgeschlossen, wie es gespeichert wurde, mit `--neu-analysieren` zuvor mit den angegebenen Optionen neu durchsucht.

## Kommandozeile

```sh
pseudonymed pseudonymisieren befund.pdf --kontakt "Müller 1959"
pseudonymed pseudonymisieren scan.pdf --patient patient.json --ocr tesseract --ner
pseudonymed pseudonymisieren gespraech.txt --kontakt "Müller 1959"          # Transkript, unscharfe Suche an
pseudonymed pseudonymisieren gespraech.srt --patient patient.json --genau   # nur exakte Treffer
pseudonymed pruefen befund_pseudonym.pdf --patient patient.json
pseudonymed rueckersetzen brief.txt --kennung K7Q4MX --form anrede
pseudonymed pseudonymisieren foto.jpg --kontakt "Müller 1959" --papier letter   # Bild auf US Letter
pseudonymed pseudonymisieren scan.pdf --patient patient.json --roh              # OCR-Text ohne Markdown
pseudonymed pseudonymisieren befund.pdf --patient ich.json --empfaenger https://example.org/arzt.asc  # für Empfänger
pseudonymed rueckersetzen brief.txt --kapsel befund_pseudonym.kapsel.asc       # Empfängerin, GnuPG-Schlüsselbund
pseudonymed schluessel erzeugen --name "Dr. Beispiel" --email arzt@example.org  # Schlüsselpaar ohne GnuPG
pseudonymed kontakte lokal ~/Kontakte/patienten.vcf                         # lokales Adressbuch
pseudonymed datenbank speicherort --datenbank ~/Sicher/pseudonymed.sqlite --schluessel ~/Sicher/schluessel.txt
pseudonymed datenbank status                                                # Statistik
pseudonymed datenbank exportieren ~/Sicherungen                             # fragt nach einer Passphrase
pseudonymed datenbank importieren ~/Sicherungen/pseudonymed_sicherung_2026-11-02_0900.zip.gpg
pseudonymed fachbegriffe ergaenzen befund_pseudonym.vokabular.txt           # ins Nutzervokabular
pseudonymed identifikatoren hinzufuegen "Musterwerk AG"                 # eigener Identifikator
pseudonymed identifikatoren pruefen "arbeitet als Tischler"            # was würde geschwärzt?
pseudonymed pseudonymisieren brief.pdf --patient p.json --dosierungen-schwaerzen --messwerte-schwaerzen
pseudonymed pseudonymisieren brief.pdf --patient p.json --arbeitsstand      # schreibt brief.arbeitsstand.pdf + .json
pseudonymed pseudonymisieren brief.arbeitsstand.json --neu-analysieren --ner   # Variante aus dem Arbeitsstand
pseudonymed pseudonyme
pseudonymed konfig
```

Rückgabewerte: 0 freigegeben, 1 Eingabefehler, 2 nicht freigegeben, 3 Pseudonyme nach der Rückersetzung offen, 4 unsicherer Abgleich (`--gleich KENNUNG` oder `--neu`).
